📥 PseudoQueue

Learning how to make a Queue using two Stacks — one small step at a time.

The Idea Why Use It? Stacks Queue Build It Test It

1. 🌱 Start With the Big Idea

🎯 Goal: We want to build something that behaves like a Queue, but we are only allowed to use two Stacks.

This is called a PseudoQueue. “Pseudo” means something that acts like something else. Our PseudoQueue will act like a Queue, even though it is built from Stacks.

📚 Stack

Last In, First Out (LIFO)

Think of a stack of cafeteria trays. The last tray placed on top is the first tray removed.

🚶 Queue

First In, First Out (FIFO)

Think of a checkout line. The first person to enter the line should be the first person served.

💡 Main challenge: A Stack naturally gives us the newest item first. A Queue needs to give us the oldest item first. We will use a second Stack to reverse the order.

2. 🌎 Why Would We Learn This?

In a real application, you would normally use the data structure or tool that best fits the job. This exercise is useful because it teaches us how data can be rearranged when the tools we have do not directly match the behavior we need.

Why two Stacks? Moving items from one Stack to another reverses their order. That reversal lets us turn LIFO behavior into FIFO behavior.
  • Task processing: jobs may need to be handled in the same order they arrived.
  • Customer requests: support tickets or requests can be processed oldest-first.
  • Printing: print jobs are commonly handled in arrival order.
  • Messaging: applications often need to preserve the order in which messages arrive.
  • Learning problem solving: sometimes programmers must build one behavior from simpler tools already available to them.

The important lesson is not that every real queue should literally be built from two Stacks. The lesson is understanding how data structures control the order in which data is added and removed.

3. 📚 Milestone 1 — Remember How a Stack Works

Milestone: Create a Stack and practice push(), pop(), and peek().

We will use our own simple Stack class. It stores Nodes linked together from the top.

const practiceStack = new Stack();

practiceStack.push("Book A");
practiceStack.push("Book B");
practiceStack.push("Book C");

console.log("Top item:", practiceStack.peek());
console.log("Removed:", practiceStack.pop());
console.log("New top:", practiceStack.peek());
Expected console: Top item: Book C Removed: Book C New top: Book B

Notice that Book C went in last and came out first. That is LIFO.

4. 🚶 Milestone 2 — Understand What Our Queue Must Do

Suppose these three students join a line:

FRONT BACK ↓ ↓ [Ana] → [Ben] → [Carlos]

The correct removal order is:

Ana
Ben
Carlos

Ana entered first, so Ana must leave first. Our two Stacks need to produce this same result.

5. 🏗️ Milestone 3 — Create the PseudoQueue

Our PseudoQueue owns two Stack objects:

class PseudoQueue {
  constructor() {
    this.inputStack = new Stack();
    this.outputStack = new Stack();
  }
}

📥 inputStack

New values arrive here.

📤 outputStack

Values leave the Queue from here.

Milestone check: console.log("PseudoQueue created with two Stacks.");

Milestone 4 — Enqueue

enqueue(value) means add a value to the back of the Queue. This part is simple: push the new value onto inputStack. 

enqueue(value) {
  this.inputStack.push(value);
}

If we enqueue Ana, Ben, and Carlos, our input Stack looks like this:

inputStack TOP → Carlos Ben Ana

There is a problem: pop() would give us Carlos, but our Queue needs Ana first.

Milestone 5 — Use the Second Stack to Reverse the Order

When we need to dequeue and outputStack is empty, we move every value from inputStack to outputStack.

BEFORE MOVING AFTER MOVING inputStack outputStack TOP → Carlos TOP → Ana Ben Ben Ana Carlos

Moving the values reversed them. Now Ana — the oldest value — is on top. 

while (!this.inputStack.isEmpty()) {
  const movedValue = this.inputStack.pop();
  this.outputStack.push(movedValue);
}

Milestone 6 — Dequeue

dequeue() means remove the oldest value from the Queue.

  1. Check whether outputStack is empty.
  2. If it is empty, move everything from inputStack into it.
  3. Pop the top of outputStack.
  4. Return that value.
dequeue() {
  if (this.outputStack.isEmpty()) {
    while (!this.inputStack.isEmpty()) {
      this.outputStack.push(this.inputStack.pop());
    }
  }

  return this.outputStack.pop();
}
💡 Important: We only move the values when outputStack is empty. If it still has values waiting to leave, we keep using them first.

6. 🧪 Milestone 7 — Put Everything Together

Open the browser console and watch the JavaScript file explain each step.

const line = new PseudoQueue();

line.enqueue("Ana");
line.enqueue("Ben");
line.enqueue("Carlos");

console.log(line.dequeue()); // Ana
console.log(line.dequeue()); // Ben

line.enqueue("Diana");

console.log(line.dequeue()); // Carlos
console.log(line.dequeue()); // Diana
Expected order: Ana Ben Carlos Diana

What did we prove?

Even though both internal containers are Stacks, our PseudoQueue behaves like a Queue:

📥 First value IN → 📤 First value OUT
Two LIFO Stacks worked together to create FIFO behavior.

🧪 Edge Case — Empty Queue

What happens if both Stacks are empty? There is nothing to remove. Our example returns null and prints a helpful message.

Expected console: ⚠️ The queue is empty. Nothing to dequeue.
