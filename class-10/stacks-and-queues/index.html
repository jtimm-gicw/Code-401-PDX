Stacks & Queues — A visual refresher before we build them with Linked Lists

🎯 Goal

Before starting the challenge, refresh your memory about two ways of organizing data: Stacks and Queues.

Then use what you already know about Nodes and Linked Lists to build both data structures.

🧠 Part 1 — What Are Stacks & Queues?

A data structure is simply a way to organize information so a program can use it efficiently.

📚 Stack

Think about a stack of plates. You normally put a new plate on the top, and you take a plate from the top.

LIFO Last In, First Out

🚶 Queue

Think about people waiting in line. A new person joins the back, and the person at the front gets served first.

FIFO First In, First Out

📚 Stack = LIFO

What does LIFO mean?

Last In, First Out.

The last thing you add is the first thing you remove.

🥞 A
←
🥞 B
←
🥞 C
TOP

If C was added last, C comes off first.

Real-world examples

  • ↩️ Undo in a program
  • 🌐 Browser history — going back through recent pages
  • 🍽️ A stack of plates
  • 📦 A stack of boxes
  • 💻 Function calls on the call stack

Important Stack Words

push

Add something to the top.

pop

Remove something from the top.

peek

Look at the top value without removing it.

isEmpty

Check whether the stack contains anything.

🚶 Queue = FIFO

What does FIFO mean?

First In, First Out.

The first thing you add is the first thing you remove.

👤 A
FRONT
→
👤 B
→
👤 C
BACK

If A arrived first, A gets served first.

Real-world examples

  • 🎟️ People waiting in line
  • 🖨️ Print jobs waiting for a printer
  • 💬 Messages waiting to be processed
  • 🍔 Orders waiting in a restaurant kitchen
  • 🚦 Cars waiting at a traffic light

Important Queue Words

enqueue

Add something to the back.

dequeue

Remove something from the front.

peek

Look at the front value without removing it.

isEmpty

Check whether the queue contains anything.

⚖️ Stack vs Queue

📚 Stack

  • LIFO
  • Last in → first out
  • Add at the top
  • Remove from the top
  • push()
  • pop()
  • peek()

🚶 Queue

  • FIFO
  • First in → first out
  • Add at the back
  • Remove from the front
  • enqueue()
  • dequeue()
  • peek()
⭐ Easy memory trick:

Stack = plates. You work from the top.

Queue = line. People enter at the back and leave from the front.

🚀 Part 2 — Now Let's Build Them!

The challenge is called stack-and-queue.

You already have experience with Linked Lists. This time, we will use a Linked List as the underlying storage for our Stack and Queue.

👨‍🏫 Teacher Tip: Don't think of Stack and Queue as completely new ideas. Think of them as different rules for using Nodes.

🔗 Step 1 — The Node

A Node stores two important things:

  1. value — the information we want to store
  2. next — a pointer to the next Node
class Node {
  constructor(value) {
    this.value = value;
    this.next = null;
  }
}

Remember: null means there is currently no next Node.

📚 Step 2 — Build the Stack

A Stack starts with a property called top.

this.top = null;

An empty Stack has no top Node, so top starts as null.

1️⃣ push(value)

Add a new Node to the top.

Performance: O(1) — we can add it directly without walking through the list.

2️⃣ pop()

Remove the Node at the top.

Return the removed Node's value.

If the Stack is empty, raise an exception.

3️⃣ peek()

Look at the value at the top without removing it.

If the Stack is empty, raise an exception.

4️⃣ isEmpty()

Return true when the Stack is empty.

Return false when the Stack contains Nodes.

🚶 Step 3 — Build the Queue

A Queue starts with a property called front.

this.front = null;

An empty Queue has no front Node, so front starts as null.

1️⃣ enqueue(value)

Add a new Node to the back of the Queue.

Performance: O(1) — your implementation should be able to add directly at the back.

2️⃣ dequeue()

Remove the Node at the front.

Return the removed Node's value.

If the Queue is empty, raise an exception.

3️⃣ peek()

Look at the value at the front without removing it.

If the Queue is empty, raise an exception.

4️⃣ isEmpty()

Return true when the Queue is empty.

Return false when the Queue contains Nodes.

🧩 The Big Picture

The most important idea is that the Node and Linked List give us the building blocks. Stack and Queue tell us how those Nodes should be used.

Stack Rules

⬆️ Add at TOP

⬆️ Remove from TOP

🔄 LIFO

Queue Rules

➡️ Add at BACK

⬅️ Remove from FRONT

🔄 FIFO
