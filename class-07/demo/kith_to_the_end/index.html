Linked List: Kth From the End

Using two pointers to find a node from the tail

What Does "Kth From the End" Mean?

We want to find a node by counting backward from the tail of the linked list.

HEAD
→
B
→
C
→
D
→
E
TAIL

With this list:

k = 0 E
k = 1 D
k = 2 C
k = 3 B
k = 4 A

The Two-Pointer Strategy

We can solve this problem efficiently by using two pointers: FAST and SLOW.

1
Start both FAST and SLOW at the head.
2
Move FAST forward by k positions.
3
Move FAST and SLOW together.
4
When FAST reaches the tail, SLOW is pointing at the kth node from the end.

// Returns: "C"

The Important Part of the Code

The key idea is to keep FAST exactly k positions ahead of SLOW.

let fast = this.head;
let slow = this.head;

// Move FAST k positions
for (let i = 0; i < k; i++) {
  fast = fast.next;
}

// Move both pointers
while (fast.next !== null) {
  fast = fast.next;
  slow = slow.next;
}

return slow.value;

Edge Cases

Edge Case #1: k Is Too Large

Our list contains:

A → B → C → D → E

But we ask for:

list.kthFromEnd(5);

There is no valid node at that position. The method returns null.

Edge Case #2: Empty List

What happens when the list contains no nodes?

const list = new LinkedList();

list.kthFromEnd(0);

There is no node to return, so the method safely returns null.

Big-O Complexity

Time: O(n)

We move through the linked list once.

Space: O(1)

We only use two pointers.
