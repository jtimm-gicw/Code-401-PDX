01 / The big idea

What is a hash table?

Imagine a filing cabinet. Instead of opening every drawer to find a document, a rule tells you exactly which drawer to look in. A hash table works in a similar way.

🏷️

Key

The label we search with: "cat"

📄

Value

The information attached to the key: "Milo"

⚙️

Hash function

A repeatable rule that converts the key into an array index.

🗄️

Bucket

A storage slot inside the underlying array.

💥

Collision

Two different keys land in the same bucket.

🚀

Why use one?

Quickly find a student grade, username, price, or inventory quantity.

📣 Tell students: The key is what we look up. The value is what we want to find. The hash function tells us where to look.

04 / Code challenge requirements

The five methods you must build

Every method should have one clear job. The hash() method is reusable: set(), get(), and has() call it.

1. hash(key)

Convert the key into a valid index in the underlying array.

hash("cat") // 2

2. set(key, value)

Add a pair. If the key already exists, replace its value. Handle collisions.

set("cat", "Milo")
set("cat", "Luna") // update

3. get(key)

Search the correct bucket and return the matching value. Return undefined for a missing key.

get("cat") // "Luna"

4. has(key)

Return true if the key exists; otherwise false.

has("cat") // true

5. keys()

Return an array of every key stored in the table.

keys() // ["cat", ...]

⚠️ Important edge cases

Duplicate keys, missing keys, keys sharing a bucket, and values like 0, false, or undefined.

06 / Interview preparation

How to explain this on a whiteboard

🎤 What the student should say

“I use hash(key) to choose a bucket. Then I store or find the key–value pair in that bucket. If two keys land in the same bucket, I compare the original keys so I find the correct entry.”

🧠 Follow this order

  1. Restate the problem.
  2. Identify normal and edge cases.
  3. Draw five buckets and a collision.
  4. Explain the algorithm in plain words.
  5. Write pseudocode, then JavaScript.
  6. Dry-run the result and explain Big-O.

⏱️ Big-O, explained simply

Average set/get/has: O(1) with a well-distributed hash and controlled bucket sizes. This means lookup is usually fast.

Worst case: O(n) when lots of keys collide and one bucket must be searched.

keys(): O(n) because it must collect all n keys.

Important detail: Our example hash(key) takes O(k) for a key of length k, because it visits each character. Our simple function is for learning—not production security or performance.

✅ Success check: Can students explain what the key and value are, why hashing picks a bucket, what a collision is, why updating an existing key must not add a duplicate, and why worst-case lookups can be slow?
